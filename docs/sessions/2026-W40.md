### 2026-09-29 (Tuesday)

- The lead asked whether the MultiScale architecture raises Folded Lens
  recall. Answered with a five-run sweep on the VM, one model at a time on the
  A100, all five inside one session: the four architectures of
  `notebooks/FMD_ResNet50Architectures.ipynb` plus plain ResNet50 as the
  control, same recipe and split as `ml_resnet50_base`. 59 minutes wall clock,
  every run exit 0.
- Port first, then train. `train.py` gained the four architectures behind
  `--arch`, faithful to the notebook on filter counts, taps, fusion widths and
  head; the single change is the final layer, five independent scores instead of
  the notebook's softmax, because one image can carry several tags.
  `verify_archs.py` proved the port before anything trained: 38 checks, 0
  failed, parameter counts reconciled row by row with the Keras 22-class line,
  the only gap being BatchNorm accounting (proved by hand). A real-image smoke
  passed for all five architectures, with the taps checked after a forward pass
  rather than before one.
- Result: MultiScale does not lift Folded Lens. FL recall is 0 in all five rows;
  the four architectures put every one of the 36 Folded Lens test images below
  zero, while the control keeps 8 above zero and catches 1 to 6 as the threshold
  drops. FL AUPRC falls from 0.582 in the control to 0.44 to 0.51. Macro AUPRC
  falls 0.028 to 0.054 on all four; macro F1 moves -0.001 to +0.019.
- The control re-run also measured the run-to-run band for the first time on
  this line: same config, same seed, same split, new session gives macro F1
  0.80826 to 0.77118 (-0.037), exact match -0.018, macro AUPRC +0.011, FL F1
  0.103 to 0.000. That band is wider than every architecture delta in the sweep,
  so only the categorical result is read as an architecture effect.
- Timing, no warmup anywhere: in-process first pass 3.285 to 3.471 ms per image,
  fresh-process first pass 3.461 to 3.817 ms per image (process start, CUDA init
  and checkpoint load inside the number), first batch 355 to 514 ms, steady
  repeats 3.23 to 3.33 ms, training 500.6 to 947.9 s, which is 1.2x to 1.9x the
  control. Inference per image is flat across architectures; training is not.
- Housekeeping after the sweep: the transfer staging folders that sat in the shared
  login home on the VM (`ml_archs_stage`, `multilabel_stage`, plus the helper
  scripts) were removed, since every file in them was md5-identical to its copy in
  the pranayp run tree and nothing was unique to them. Record of what was removed
  and its md5sums: `run/multilabel_lp_archs_20260929/stage_cleanup_20260929.txt`.
  One file in that home is not ours and was left alone: `cold_infer_all.sh`
  (2026-09-29 04:53), which produced the first three fresh-process timing files.
- Post-run: 75-check independent recompute of every headline metric and all 20
