## Layout

The blob holds no class folders, so the local tree mirrors the container layout
and keeps the labels in the XML where the annotator put them. We added only the
`annotations/` and `images/` split, for readability.

```
PRODUCTION_20260925/
├── annotations/annotations_4521940.xml ... 4521946.xml
├── images/*.bmp
└── manifest.csv
```

Image basenames are unchanged from the blob, so the image names inside the XMLs
resolve against `images/` by basename with no remapping. Full resolution of the
in-XML path `FMD_PROD/PRODUCTION-20260925/<name>.bmp` needs a root that points
at `images/` with that prefix stripped.

## Why we pulled 1,047 and not the whole folder

The image container holds 10,438 blobs under `FMD_PROD/PRODUCTION-20260925/`,
52,342,206,916 bytes (48.75 GB). Only 1,047 of them are referenced by these
annotations, so we took the annotated subset at 5.24 GB and left 9,391 images
in blob as potential negatives for a later pull.

## Findings that came out of the pre-move checks

**These images were already on the VM.** All 1,047 annotated images existed under
`fmd_temp_images/` inside the 2026-09-15 libraries, as 1,696 files because of
duplication: 416 images with one copy, 614 with two, 16 with three, 1 with four.
Sampled against the blob's own `content_md5`, 14 of 14 copies were byte-identical,
so the local files were good and the pull was a deliberate fresh copy into a
clean tree, not a repair.

**The library folder labels disagree for 113 images.** The same bytes sit in
different class folders across the three libraries: 35 as `Bubble` vs `Clear`,
30 as `Wet Package` vs `Clear`, 16 as `Dirty Strobe` vs `Clear`, 14 as
`Bubble Cluster` vs `Clear`, 10 as `Low Dose Obstructing Region of Interest` vs
`Low Dose`, plus `Fiber` vs `Extraneous Polymer` and `HEMA Fragment` vs `HEMA`.
No single library puts one file in two classes by itself, so this is the
libraries disagreeing with each other. The new XMLs are the authority over
folder names from here.

**Consequence for splits.** Globbing the existing libraries for a training set
would feed 1,696 paths for 1,047 unique images, which leaks the same pixels
across a split. The pulled tree has each image exactly once, and the manifest
plus the XMLs carry the multi-label truth, so a split should be built from the
manifest rather than from any folder walk.
