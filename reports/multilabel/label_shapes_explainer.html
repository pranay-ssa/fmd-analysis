Four pictures, four situations

Every picture we hold is one of these four. The distinction that decides the model is never "how many labels" on its own: it is which tier the labels live in and whether they describe one object or several.

1. Several objects, all one class

SituationWhat the training file holds
A Bubble Cluster frame. Real example from our data: 1,298 Bubble boxes sit on 113 pictures, and the busiest single picture holds 38 boxes.

multi-instance, single class

Three objects, one name. This is not multi-label, and YOLO trains on it today.

5 0.44 0.55 0.019 0.017
5 0.39 0.49 0.022 0.020
One row per object. One class number, three times.

2. Two objects, two classes on one picture

SituationWhat the training file holds
A frame holding a Fiber at the top left and a Bubble at the bottom right.

multi-class detection

This is exactly what "can YOLO take two box labels on one picture" means. It is supported with no code change, and it is the tool's own documented example. Our data holds 0 such pictures today, only because the annotation ran one job per class. 
3 0.31 0.22 0.040 0.030
7 0.72 0.66 0.060 0.050
Class numbers are placeholders for the index in that arena's name list. The point is that the two rows carry two different numbers.

3. One object, two folder labels (not two defects)

SituationWhat the training file holds
33 of our 55 multi-label pictures are this. The newer folder files the stringy excess lens material as Extraneous Polymer; the older library files the same picture as Fiber.

one defect, two names

The count says "multi-label", reality says "two sources disagree". It needs a taxonomy decision from the client, not a model that predicts two things at once.

4. A frame-level tag plus an object

SituationWhat the training files hold
A frame whose lens has shifted (Lens Off Center, a tag: a property of the whole frame) and which also shows saline under the package edge (Wet Package, an object: something you can point at).

two tiers, two models

The picture appears in both inputs: once as a tagged row, once with its boxes. 13 of our 8,409 pictures are this shape today, and this is the shape production will have.

Why the loss function decides what is possible

A picture that really is under-dosed and has a dirty strobeWhich head can say it
softmax output (one answer, the numbers sum to 1)
low dose     0.91
dirty strobe 0.04
multiple lenses 0.03
(the rest)   0.02  -> sum 1.00
Softmax is built on "exactly one of these is right". Raising one answer must lower the others. It physically cannot report both.
sigmoid output (one yes/no per tag, no sum)
low dose     0.93
dirty strobe 0.81
multiple lenses 0.12
Thirteen independent questions. Any number can be high, including all of them. This is the head the tag tier needs.

And a detector has no picture-level class at all. The class number belongs to each box, not to the frame. That is why "YOLO cannot do multi-label" is the wrong question for boxes: there was never a single class per picture for it to fail at.
